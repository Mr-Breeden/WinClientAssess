Assessment staging and ACL interpretation
For repeatable tests, consider an approved dedicated staging directory (for example C:\Assessments\Targets). Verify its permissions independently: moving a target does not automatically provide secure or representative ACLs. User-profile installations can be legitimate and may still expose real trust-boundary issues. WCA never treats the assessor's own write access as proof of a vulnerability.
Tester-controlled execution
All assessment stages run in a private background worker with live status and explicit browser checkpoints. Full assessment requires an elevated WCA process to collect privileged evidence. The browser never installs, launches, or exercises the target. No exploit or PoC is executed by the GUI.

  1. Verify collection and review gaps in coverage_summary.txt and module_status.txt.
  2. Disposition related candidates directly inside each Testing Queue activity.
  3. Use the Testing Queue to complete applicable manual test cases and related WCR candidate reviews together.

TC-PE-001 · Independent PE / CFG verification (optional)

One-click DUMPBIN review: Choose all, flagged, or one PE file from this verified assessment. Click Run to inspect binary metadata and receive a readable three-indicator CFG analysis. DUMPBIN reads the file without launching the target. PESecurity remains optional and is never imported automatically.




Step 1 · Choose the PE files










Step 2 · Run DUMPBIN and analyze CFG


WCA invokes the configured dumpbin.exe /headers /loadconfig once per file and explains Guard, CF instrumented, and FID table present. A separate evidence folder and summary are created automatically alongside your assessment; no original report is changed.



Open a verified assessment to enable this action.




Step 3 · Review results


All three present means expected CFG metadata verified, not runtime mitigation proof. Missing metadata requires contextual review, not an automatic vulnerability. An unavailable tool, failed command, or unreadable file is inconclusive.











Advanced · Manual CMD commands and optional PESecurity

DUMPBIN is a separate manual check. WCA's CFG result is the PE header GUARD_CF bit, not proof that CF Instrumented and FID table present are set. Use the Visual Studio Developer Command Prompt (CMD, not PowerShell) for the DUMPBIN commands. The advanced CMD buttons copy commands only; they do not execute tools.


Verify three indicators: Guard under characteristics and CF Instrumented plus FID table present under load-configuration Guard Flags. PESecurity is a separate optional PowerShell cross-check.


Open TC-PE-001 to resolve PE paths from the current integrity-verified assessment.



























Paths for manual commands are resolved locally from the verified PE report, including WCA's %USERPROFILE% privacy placeholder; no report is modified. Paste or save the downloaded one-path-per-line list outside WCA's protected assessment directory, enter its actual full path above, and create the evidence folder yourself. The interactive CMD loop uses %I; a saved .bat/.cmd file uses %%I. Batch output names use the source basename, so duplicate basenames can overwrite earlier outputs; use individual commands for collisions. Review outcomes in your engagement evidence, not in original WCA reports.
