Assessment staging and ACL interpretation
For repeatable tests, consider an approved dedicated staging directory (for example C:\Assessments\Targets). Verify its permissions independently: moving a target does not automatically provide secure or representative ACLs. User-profile installations can be legitimate and may still expose real trust-boundary issues. WCA never treats the assessor's own write access as proof of a vulnerability.
Tester-controlled execution
All assessment stages run in a private background worker with live status and explicit browser checkpoints. Full assessment requires an elevated WCA process to collect privileged evidence. The browser never installs, launches, or exercises the target. No exploit or PoC is executed by the GUI.

Manual Test Cases
Recommended assessment sequence
  1. Verify collection and review gaps in coverage_summary.txt and module_status.txt.
  2. Disposition related candidates directly inside each Testing Queue activity.
  3. Use the Testing Queue to complete applicable manual test cases and related WCR candidate reviews together.
  4. Use the contextual supplemental guidance only for applicable attack surfaces not already addressed in the Testing Queue.
  5. Retest potential findings with technical evidence and provenance recheck commands. Capture appropriate engagement evidence.
  6. Reconcile incomplete coverage, then generate the Client Appendix from Final Checklist (integrity is automatically verified).
Tests are never executed automatically. Manual COMPLETED does not mean a vulnerability was confirmed. Tester notes are optional.
